# Authentication and permissions

Production identity uses Better Auth backed by the `users`, `accounts`, `sessions`, `auth_verifications`, and `auth_rate_limits` tables. Email/password sign-in requires verified email, passwords are 12–128 characters, reset invalidates existing sessions, and production auth endpoints use database-backed rate limits. Verification, password-reset, and owner-invitation messages are delivered through Resend. Each request carries a payload-derived idempotency key, transient network/rate-limit/provider failures receive bounded retries, permanent configuration/quota errors fail immediately, and successful sends record only the provider delivery ID in server logs. The explicitly development-only role cookie is rejected when `NODE_ENV=production`.

Roles are Visitor, Owner, Assistant Commissioner, Commissioner, and System Administrator. Commissioner authority is scoped through `league_memberships`; owner access is scoped to a franchise and league season through `franchise_memberships`; platform administration is stored separately. Assistant commissioners can operate league workflows but cannot administer identities, invitations, or owner/commissioner access. Only commissioners and system administrators receive `manage_owners`; only system administrators receive `manage_platform`. The request-scoped viewer resolves an effective role and active franchise from those durable records. `requirePermission` and `requireApiPermission` run inside protected server pages, actions, and handlers. UI hiding is never the authorization boundary.

Active franchise members may edit the display name, abbreviation, colors, and HTTPS logo of only their assigned franchise. Commissioners may edit any franchise in their league. Both paths use the same durable action, enforce league and franchise scope server-side, retain prior names as historical aliases, and write an audit record; owner assignments and primary-owner status remain commissioner-only.

`/league/teams` is the authenticated member directory. It lists only active league members and their current-season franchise assignments; private email addresses are never loaded for a visitor or an authenticated account without active league access. Franchise profiles remain publicly useful without exposing owner contact data.

Public registration is disabled by default. A commissioner creates a seven-day, single-use invitation for an exact normalized email address; accepting it transactionally grants the league/franchise memberships and appends an audit record. Commissioners can change accepted league roles, revoke league-wide access (which also disables that user's current-season franchise memberships), or restore a franchise membership and its required league account. Those operations, invitation revocation, primary-owner changes, and franchise identity/branding changes are league-scoped and audited. The last active commissioner and the acting commissioner's own access cannot be removed through these controls. Active-franchise selection uses an HTTP-only same-site cookie and is accepted only after membership validation.

Invitation acceptance locks the invitation before granting access, so concurrent replays produce exactly one winner and one acceptance audit. Commissioner role/access mutations lock the league membership set before enforcing the last-commissioner rule. Franchise ownership mutations coordinate on the franchise row; restoring the first active owner makes that owner primary, and removing a primary owner promotes the oldest remaining active membership. Destructive owner-administration controls require confirmation and display the server action's success or failure instead of silently submitting.

Authenticated accounts can update their display name, change their password while revoking other sessions, inspect active sessions, and explicitly sign out every other device. Session management uses Better Auth's fresh/sensitive-session checks rather than trusting client state.

Mutation inputs use Zod, same-site HTTP-only cookies protect session and development flows, security headers are set globally, and credentials stay server-only. Production requires `DATABASE_URL`, `BETTER_AUTH_SECRET`, `BETTER_AUTH_URL`, `BETTER_AUTH_TRUSTED_ORIGINS`, `AUTH_EMAIL_FROM`, and `RESEND_API_KEY`. There is no public-registration override: account creation requires either an invitation token or the exact one-time bootstrap email. For the first commissioner only, set `AUTH_BOOTSTRAP_COMMISSIONER_EMAIL` after the MFL sync has created the league, register that address, complete email verification, confirm commissioner access, and immediately remove the variable. The bootstrap grant locks the league, is idempotent for the configured account, is league-scoped and audited, and closes the route automatically as soon as an active commissioner exists. If account creation succeeds but the post-create league grant is interrupted, the exact verified account can sign in and complete the same one-time grant without creating a duplicate audit.

Object-level access must always join the requested league/franchise to the current membership to prevent insecure direct-object references. A future support-session model should use separate time-limited records, explicit consent, and comprehensive audit logs—never commissioner impersonation.
